# 2단계 디자인 인계

기준일: 2026-10-30 (Asia/Seoul).

이 문서는 HongSik BlogWorld용 Figma PC·모바일 시안의 내용과 다음 단계 인계 기준을 정리한다.
2단계의 산출물은 Figma 디자인이며, 실제 웹 화면·인터랙션·공개 배포의 완료를 의미하지 않는다.

## 확정 정보와 출처

| 항목 | 기준 |
| --- | --- |
| 이름·브랜드 | HongSik BlogWorld, 사용자가 제공한 초록 H 로고·동일 파비콘 |
| 타깃 | 자료 준비·AI 글 작성·발행을 반복하는 개인 운영자와 소규모 사업자, 상위 노출을 목표로 키워드 선정을 자동화하고 싶은 운영자 |
| 주요 문의 | `support@hongsik.blog` |
| 문의 링크 | `mailto:support@hongsik.blog` |
| 최종 배포 주소 | `https://blogworld.hongsik.blog` — 실제 배포 확인은 6단계 |
| 디자인 원본 | 사용자가 선택하고 복제한 SaaS Landing Pages (Biccas) |

타깃은 사용자 확정 사항이다. 키워드 자동화의 구체적인 제공 범위를 검증한 것으로 해석하지 않는다.
시안의 기능 표현은 확인된 작업 흐름에 맞춰 ‘키워드 선정 지원 → 자료 준비 → AI 원고 작성 → 검토·발행’으로 사용한다.

| 원본 요소 | 적용 방향 |
| --- | --- |
| 넓은 여백, 초록 포인트, 검정 타이포그래피 | 브랜드 전용 PC·모바일 시안의 기본 분위기로 참고 |
| 첫 화면의 큰 제목·설명·두 가지 CTA | 한국어 메시지와 사용 문의·사용 과정 보기로 구성 |
| 기능 카드·교차 설명·라운드 버튼 | 역할별 재사용 컴포넌트와 반응형 배치로 구성 |
| 어두운 문의·푸터 영역 | 실제 이메일 문의와 운영 정보에 맞춰 구성 |

| 25,000개 팀·평점·고객사 로고·후기 | 근거 없는 앱 실적으로 사용하지 않음 |
| 무료 체험·요금제·가입 버튼 | 확정된 사용 문의와 사용 흐름 안내로 교체 |
| 일반 문의 폼·뉴스레터 폼 | 발송 서버가 있는 것으로 보이지 않도록 이메일 링크와 주소 안내로 구성 |

원본 템플릿 프레임은 보존한다. 브랜드 시안은 별도 페이지 또는 명확히 구분된 프레임에 둔다.
참고 출처는 [SaaS Landing Pages](https://www.figma.com/community/file/1117683989281342298)로 남긴다. [Figma 공식 설명](https://www.figma.com/ai/our-approach/)은 무료 Community 파일의 CC BY 4.0 적용과 출처 표기를 안내한다. 이번 원본 상세 페이지는 웹 도구로 열리지 않아 개별 작성자·별도 조건까지 확인했다고 주장하지 않는다. 공개 단계에서 출처 표기를 다시 확인한다. 원본 인물 사진·금융 이미지·고객사 로고는 이번 시안에 복제하지 않았다.

## 화면 구성과 카피

아래 문구는 시안 적용 기준이다. Figma에 반영된 최종 줄바꿈·표기와 다르면 인계 전에 이 문서와 함께 맞춘다.

### Header

- 브랜드: `HongSik BlogWorld`와 초록 H.
- 메뉴: `주요 기능`, `사용 과정`, `자주 묻는 질문`.
- 주요 CTA: `사용 문의`.
- 역할: 브랜드와 페이지 내 이동, 문의 경로를 짧게 제공한다.

### Hero

- 제목: **키워드 선정부터 블로그 발행까지, 흐름을 하나로.**
- 상단 짧은 문구: `나의 블로그, 나의 작업 흐름`.
- 설명: **자료 준비와 AI 글 작성·발행을 반복하는 블로그 운영자를 위해. HongSik BlogWorld에서 쓸 주제와 참고 자료를 정리하고 원고를 검토하세요.**
- 보조 문구: `개인 운영자와 소규모 사업자를 위한 Windows 앱`.
- 주요 CTA: `사용 문의` → `mailto:support@hongsik.blog`.
- 보조 CTA: `사용 과정 보기` → Workflow 영역.
- 우측 비주얼: 전체를 편집 가능한 Figma 텍스트·도형으로 구성한 사용 흐름 그림이다. `BLOGGING, CONNECTED`, `좋은 글은 쓸 주제에서 시작됩니다.`, `키워드부터 발행까지 이어지는 사용 흐름 예시`와 네 단계를 표시한다. 실제 앱 화면 캡처라고 설명하지 않는다.

### Benefits

- 영역 제목: **반복되는 블로그 작업을 한 흐름으로.**
- 설명: **쓸 주제를 정하고 자료를 준비한 뒤, 원고 작성과 검토·발행으로 이어가세요.**
- 핵심 메시지: `주제 선정부터 시작`, `자료와 원고를 연결`, `검토를 거쳐 발행`.
- 목적: 기능 이름만 나열하지 않고 사용자의 작업 순서와 기대효과를 연결한다. 정량적인 시간 절감·수익·노출 성과는 제시하지 않는다.

### Features

- 짧은 제목: `주요 기능`.
- 영역 제목: **블로그 운영에 필요한 과정, 따로 흩어 놓지 마세요.**
- 설명: **선정한 주제와 참고 자료를 원고 작성, 검토와 발행으로 연결합니다.**

| 카드 | 설명 |
| --- | --- |
| 쓸 주제부터 정리하세요 | 키워드를 검토하고 글의 주제를 선정하는 과정을 지원합니다. |
| 참고 자료를 준비하세요 | 원문 URL을 바탕으로 글에 활용할 자료를 준비합니다. |
| 자료를 바탕으로 원고를 작성하세요 | 준비한 자료와 설정을 활용해 AI 글 작성을 진행합니다. |
| 검토하고 발행으로 연결하세요 | 원고와 이미지를 확인한 뒤 발행 단계로 이어갑니다. |

### Workflow

- 짧은 제목: `사용 과정`.
- 영역 제목: **쓸 주제를 정한 뒤, 이 순서로 진행하세요.**
- 설명: **AI가 작성한 원고도 내용을 직접 확인하고 발행하세요.**
- 추가 CTA: `사용 문의`.

| 순서 | 제목 | 설명 |
| --- | --- | --- |
| 01 | 키워드 선정 | 운영할 블로그에 맞는 글의 주제를 정합니다. |
| 02 | 자료 준비 | 참고할 원문과 글에 활용할 자료를 준비합니다. |
| 03 | AI 원고 작성 | 준비한 자료를 바탕으로 원고를 작성합니다. |
| 04 | 검토·발행 | 내용과 이미지 구성을 확인하고 발행을 진행합니다. |

### FAQ

- 짧은 제목: `자주 묻는 질문`.
- 영역 제목: **궁금한 점을 먼저 확인하세요.**
- 설명: **더 궁금한 내용은 이메일로 문의해 주세요.**
- 첫 답변만 펼쳐 두며, 첫 아이콘은 마이너스·나머지는 플러스다.

| 질문 | 답변 |
| --- | --- |
| 어떤 분에게 어울리나요? | 자료 준비·AI 글 작성·발행을 반복하는 개인 블로그 운영자와 소규모 사업자, 키워드 선정 자동화에 관심 있는 운영자를 대상으로 합니다. |
| 어디에서 사용하는 앱인가요? | HongSik BlogWorld는 Windows에서 실행하는 앱입니다. |
| 어떤 순서로 사용하나요? | 키워드 선정과 자료 준비를 거쳐 AI 원고를 작성하고, 내용과 이미지를 검토한 뒤 발행으로 진행합니다. |
| 상위 노출을 보장하나요? | 상위 노출을 보장하지 않습니다. 블로그 운영에 필요한 키워드 선정과 글쓰기 과정을 지원합니다. |
| 사용 문의는 어디로 하나요? | support@hongsik.blog로 문의해 주세요. |

### Contact

- 제목: **내 블로그 운영에 맞는지 궁금하신가요?**
- 설명: **사용 목적과 궁금한 내용을 이메일로 알려주세요.**
- 주요 CTA: `이메일로 문의하기` → `mailto:support@hongsik.blog`.
- 주소는 버튼 외에도 `support@hongsik.blog` 텍스트로 표시한다.
- 발송 성공·접수 완료를 실제로 처리하는 문의 폼처럼 표시하지 않는다.

### Footer

- 초록 H와 `HongSik BlogWorld`.
- 태그라인: `키워드 선정부터 블로그 발행까지.`
- 하단: `© HongSik BlogWorld · blogworld.hongsik.blog`.
- 문의 주소는 바로 위 Contact 영역에서 제공한다.
- 약관·개인정보 처리방침·다운로드·가격 정책은 확인된 실제 페이지가 있을 때 연결한다. 임시 `#` 링크를 넣지 않는다.
- 운영 중인 서비스나 확정된 요금제로 오인시키는 템플릿 잔여 문구를 남기지 않는다.

## PC·모바일 시안 기준

| 항목 | PC | 모바일 |
| --- | --- | --- |
| 기준 폭 | 1440px | 390px |
| 전체 흐름 | Header → Hero → Benefits → Features → Workflow → FAQ → Contact → Footer | 같은 읽기 순서 유지 |
| Hero | 제목·설명·CTA와 화면 이미지의 관계가 분명한 배치 | 제목·설명·CTA·이미지를 세로로 정리 |
| 카드·작업 단계 | 내용과 화면 폭에 맞춘 다열 배치 | 1열 중심, 문구와 순서 유지 |
| 메뉴 | 전체 메뉴와 문의 경로 표시 | 메뉴 열기 버튼과 펼친 상태 정의 |
| 문의 | 이메일 링크·주소를 명확히 구분 | 긴 주소·버튼이 화면 폭을 넘지 않도록 배치 |

- PC 프레임 1440×3678, 모바일 390×5766, 모바일 메뉴 열림 상태 390×498.
- PC 좌우 여백 120px(내용 1200px), 모바일 24px(내용 342px). 섹션 상하 간격은 PC 80~96px, 모바일 48~64px 중심이다.
- 글꼴은 한국어 가독성을 위해 `Noto Sans KR` Regular·Medium·Bold로 통일한다. PC 주제목 64/82px, 모바일 38/52px, 영역 제목 PC 40/56px·모바일 28/40px, 본문 16/28px, 히어로 설명 18/30px다.
- 주색 `#007B50`, H 포인트 `#00C765`, 본문 `#162D28`, 보조 본문 `#526B64`, 연한 배경 `#EAF7EE`·`#F5F9F6`, 어두운 배경 `#102F26`, 테두리 `#D6E5DC`.
- 카드 모서리 24px, 큰 패널 32px, 버튼은 pill. 24개 Figma 변수·9개 텍스트 스타일·6개 로컬 컴포넌트를 사용한다. 의미 없는 장식 그림자는 넣지 않았다.
- 한글 제목의 줄바꿈은 의미 단위로 확인하며 영문 원본 제목의 줄 수를 강제로 유지하지 않는다.
- 화면 캡처를 모바일에서 지나치게 작게 축소해 읽기 어려워지지 않도록 실제 표시 크기를 확인한다.
- 텍스트는 배경 대비를 점검하고, 주요 조작 영역은 높이 44px 이상을 목표로 한다.
- Figma에서 가로 넘침·본문 잘림·겹침이 없는지 확인한다. 실제 브라우저 반응형 검증은 5단계에서 별도로 한다.

## 인터랙션 인계 기준

2단계는 필요한 상태와 동작을 정의한다. 실제 JavaScript 구현은 4단계에서 진행한다.

| 요소 | 인계할 동작·상태 |
| --- | --- |
| 모바일 메뉴 | 닫힘·열림 시안, 메뉴 항목 선택 후 닫기, 키보드 및 포커스 복귀 |
| 페이지 내 메뉴·보조 CTA | Features·Workflow·FAQ·Contact의 실제 섹션으로 이동 |
| FAQ | 접힘·펼침 상태와 답변 영역, 키보드 조작 |
| 문의 CTA | 실제 `mailto:` 링크, 주소 직접 확인 가능. 이메일 전송 성공 상태를 흉내 내지 않음 |
| 단계별 소개 | 현재 시안은 네 단계를 항상 표시한다. 탭·가상 앱 화면·새로운 상태를 임의로 추가하지 않는다 |

메일 이동은 링크, 메뉴 열기·FAQ 토글은 버튼으로 구현한다. 모션을 적용할 경우 동작 줄이기 설정을 고려한다.
화면·버튼에 무료 체험, 결제, 회원가입, 실제 AI 실행 등 범위 밖 기능이 있는 것처럼 표시하지 않는다.

## 다음 단계 인계

- 화면: `src/app/page.tsx`에서 섹션을 조합하고 `src/components/<영역>/`에 역할별로 분리한다.
- 설정: 확정 이름·도메인·문의 주소는 기존 `src/lib/site.ts`를 기준으로 한다.
- 공통 UI: shadcn/ui 기반의 버튼 스타일·Accordion·모바일 메뉴 등을 실제 화면에 사용한다.
- 자산: 공개할 수 있는 실제 앱 이미지와 로고만 로컬 파일로 관리한다. 임시 Figma 자산 URL을 런타임에 사용하지 않는다.
- 화면 비교: 3단계 이후 Figma와 실제 화면을 비교해 차이를 보정한다.
