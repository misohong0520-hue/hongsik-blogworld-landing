# 단계별 구현 계획

현재 상태: **6단계 GitHub 공개 소스·AWS 서브도메인·HTTPS 배포 및 네트워크/복구 검증 완료**. 사용자의 다음 단계 진행 요청으로 배포를 수행했다. 5단계에서 남은 실제 PC·모바일 정밀 비교·브라우저 조작·Lighthouse는 도구 연결 오류로 미완료 상태를 유지한다. 배포 성공을 해당 검수의 통과로 간주하지 않는다. `verification-stage-5.md`, `verification-stage-6.md`를 참고한다.

2026-10-30 사용자가 최신 미리보기의 큰 제목·좌우 배치·카드 스타일이 정상으로 보인다고 확인했다. 기본 배치 복구 확인이며, 나머지 정밀 검수의 완료 상태는 위와 같다.

| 단계 | 범주 | 구현 범위 | 완료 기준 |

## 확정 사항

- 이름: HongSik BlogWorld. 로고·파비콘: 사용자 제공 초록 H.
- 타깃: 자료 준비·AI 글 작성·발행을 반복하는 개인 운영자와 소규모 사업자, 상위 노출을 목표로 키워드 선정을 자동화하고 싶은 운영자.
- 주요 CTA: 사용 문의, `mailto:support@hongsik.blog`.
- 배포 주소: `https://blogworld.hongsik.blog`. AWS EC2 Nginx에서 WordPress와 경로·호스트 분리. Vercel 사용 안 함.
- 원본 시안: https://www.figma.com/design/h2yyAh96bomjU0WmO6NRiw/Saas-Landing-Pages--Community-?node-id=0-7

## 1단계 경계

상단 메뉴는 별도 페이지를 추가하지 않고 같은 랜딩페이지 안에서 이동한다. 3단계에서 기본 HTML 앵커를 연결했고 4단계에서 현재 섹션 표시·이동 후 키보드 포커스·동작 줄이기 설정을 존중하는 부드러운 스크롤을 구현했다. 메뉴 디자인은 유지한다. 브라우저 실화면과 네이티브 스크롤·이력 검증은 5단계에서 마쳐야 한다.

| 메뉴 | 연결 내용 |
| --- | --- |
| 홈 | 메인 앱 소개와 제품 이미지 |
| 기능 | 자료 준비·AI 원고 작성·검토/발행의 기능 카드 |
| 안내 | ‘어떤 과정을 도와주나요?’의 키워드·원문·작성·검토 안내 |
| 과정 | 준비 → 글 작성 → 발행의 3단계 과정 카드 |
| 문의 | 이메일 문의 영역 |

오른쪽 ‘안내’는 중앙의 안내와 같은 영역, 초록 ‘문의’는 같은 문의 영역에 연결할 계획이다. 사용자가 숨기도록 한 하단 안내 문구 3줄은 위 안내 섹션과 별개다.

1단계의 기반 확인 화면은 3단계의 실제 섹션 화면으로 교체했다. 브라우저 시안 비교 전이므로 픽셀 단위 일치나 반응형 검수 완료를 주장하지 않는다.
가격·고객 후기·다운로드 파일·회원가입·결제·AI 실행 기능은 추가하지 않는다.
최종 2단계는 별도 Figma 페이지 `115:2`의 PC·모바일 시안이다. PC는 원본 프레임을 직접 복제하고 581개 원본 노드와 비교했다. 디자인은 `docs/template-correction.md`, 검증은 `docs/verification-template-correction.md`를 따른다. `104:*` 및 기존 2단계 문서는 폐기 초안 기록이다.
