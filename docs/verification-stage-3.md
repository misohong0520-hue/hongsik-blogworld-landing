# 3단계 화면 구현·검증

기준: `4c8136f`, 작업 브랜치 `codex/landing-stage-3`.

## 구현 범위

- 최종 Figma PC `115:6`(1440×5850), 모바일 `123:5`(390×약8781)의 디자인 정보와 스크린샷을 기준으로 섹션별 TSX·CSS 모듈을 구성했다.
- `src/app/page.tsx`가 Header → Hero → 작업 라벨 → Support → Features → Benefits → Process → Contact → Footer를 조합한다.
- Next.js App Router·TypeScript·Tailwind·shadcn/ui 구조와 정적 내보내기를 유지한다. Noto Sans KR·Inter는 `next/font`로 제공한다.
- 사용자 승인 제품 이미지, 초록 H, 아래쪽 화살표를 반영했다. 숨기기로 한 안내 3줄과 반복 로고 행은 렌더링하지 않는다.
- 모바일에서는 단일 열로 전환한다. 중간 PC 폭에서 히어로 이미지와 원고 예시 카드의 돌출 폭을 화면 여백 이내로 제한했다. 1440px의 원본 배치는 유지한다.
- 이미지 자체를 보여주는 일러스트 외에는 텍스트·카드·메뉴를 HTML로 구현했다. 페이지 전체 스크린샷으로 대체하지 않았다.
- 메뉴·과정 버튼에 기본 HTML 앵커를 연결했고 문의는 `mailto:support@hongsik.blog`로 연결했다. 메일은 자동 발송하지 않는다.

## 에셋

- `public/figma/`에는 실제 참조하는 에셋 28개만 보관한다. 원본 노드와 경로는 `design/stage3-assets.json`에 기록했다.
- 기능 일러스트 3개와 작업 공간 사진은 Figma의 해당 콘텐츠 노드에서 내보냈다. 디자인 응답의 32px 사진 대체 이미지는 실제 450×529 사진으로 교체했다.
- 원본 인물, 숨긴 그래픽, 중복 제품 이미지 등 사용하지 않는 파일은 제외했다.
- 임시 Figma 다운로드 주소와 원시 응답은 저장소에 넣지 않는다. 런타임은 로컬 에셋을 참조한다.
- 공개 배포 전 템플릿과 개별 사진·일러스트의 이용 조건을 최종 확인한다.

## 남은 검증

사용자가 브라우저 사용과 Browse 권한을 켰다고 확인한 뒤 도구 세션을 초기화하고 다시 연결했지만 `Local browser use is disabled in Work settings`가 반환됐다. 따라서 실제 브라우저 화면·이미지 로딩·콘솔·키보드·앵커 이동은 확인하지 못했다. 설정을 임의 변경하거나 다른 자동화 경로로 우회하지 않았다.

연결 복구 후 1440px·390px 시안 비교와 320px·768px·1250px 중간 폭의 잘림을 확인해야 한다. 화면 글꼴·줄바꿈·높이까지 일치한다고 주장하지 않는다.

4단계 JavaScript 인터랙션, 5단계 최종 접근성·메타정보·Lighthouse, 6단계 GitHub·AWS·DNS·HTTPS는 아직 진행하지 않았다. 기존 데스크톱 앱·프롬프트·계정·DB·WordPress는 수정하지 않았다.
