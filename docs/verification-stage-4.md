# 4단계 인터랙션 구현·검증

기준 커밋 `e93e16a`, 브랜치 `codex/landing-stage-4`.

## 변경한 동작

- 상단 메뉴의 고정 ‘홈’ 표시를 현재 보고 있는 섹션에 따라 갱신한다. 현재 링크 하나에만 `aria-current="location"`을 제공한다.
- 페이지 전체를 감싼 `#home`의 교차 여부 대신 실제 기능·안내·과정·문의 섹션의 위쪽 경계를 읽는다. 스크롤·리사이즈 처리는 프레임당 한 번으로 묶는다.
- 기본 앵커 이동 후 해당 섹션 제목에 포커스를 준다. 본문 바로가기는 `main`으로 연결한다. 포커스 이동으로 스크롤을 다시 움직이지 않도록 `preventScroll`을 사용한다.
- 직접 해시 주소 진입, 현재 해시 재실행, 해시 변경을 처리한다. 해시 없는 최초 방문은 포커스를 빼앗지 않으며, 해시 없는 주소로 돌아오면 홈 제목으로 포커스를 옮긴다.
- 프로그램 포커스에 필요한 `tabindex=-1`은 임시로 추가한다. 기존 tabindex는 보존하며 blur·언마운트 시 정리한다.
- 기본 링크 동작·브라우저 이력은 가로채지 않는다. 수정키·중간 클릭·새 탭·다운로드·이미 취소된 클릭은 보완 처리에서 제외한다.
- `prefers-reduced-motion: no-preference`일 때만 부드럽게 스크롤한다.

과정의 ‘사용 과정/문의하기’는 실제 섹션 링크이며 탭·패널로 바꾸지 않았다. 메일 문의는 기존 mailto를 유지한다. 새 카드·모바일 메뉴·폼·백엔드·앱 연결은 추가하지 않았다.

## 파일 책임

- `src/components/header/header-navigation.tsx`: 현재 섹션 상태와 메뉴 표시를 담당하는 작은 Client Component.
- `src/components/navigation/anchor-focus.tsx`: 앵커 후 포커스만 보완하는 Client Component. 추가 화면 요소는 렌더링하지 않는다.
- 기존 페이지와 다른 섹션은 Server Component로 유지한다.
- `tests/navigation.test.mjs`: 기존 TypeScript·React와 개발 전용 Happy DOM으로 실제 두 컴포넌트의 이벤트·포커스·상태 변화를 검사한다. CSS 모듈 이름과 레이아웃 좌표 입력을 테스트 환경에서 대체한다.

## 검증

| 항목 | 결과 |
| --- | --- |
| `npm run typecheck` | 통과 |
| `npm run test:interactions` | DOM 단위 테스트 8개 통과 |
| `npm run build` | 통과, 정적 내보내기 유지 |
| `node scripts/verify-export.mjs` | 통과, 앵커 28개·에셋 경로 44개 유지 |

테스트는 초기 포커스·직접 해시·섹션 제목 이동·본문 바로가기·기존 tabindex 보존·동일 해시 재실행·수정키 등 제외 조건·빈 해시로 복귀·잘못된 해시·정리·현재 메뉴 상태를 확인한다.

테스트 환경은 메모리상의 DOM이다. 외부 페이지·메일 앱은 열지 않고 네트워크 이동을 막는다. 실제 브라우저 엔진이나 라이브 페이지를 조작하는 대체 자동화가 아니며, CSS 배치·네이티브 스크롤·뒤로/앞으로 가기 자체·새 탭 열기·메일 앱 실행을 검증한 것은 아니다. 확인한 것은 해당 이벤트에 대한 컴포넌트의 포커스·상태 처리다.

## 남은 검증

이번 단계에서도 브라우저 도구가 `Local browser use is disabled in Work settings`를 반환했다. 사용자에게 동일한 설정 변경을 반복 요청하거나 다른 경로로 우회하지 않았다.

5단계에서 실제 PC·모바일 시안 비교, Tab→Enter→목적지→다음 Tab, 같은 링크 재실행, 초기 직접 해시, 뒤로/앞으로, 수정키·새 탭, 모션 줄이기, 앵커 스크롤·콘솔·메일 링크를 확인해야 한다. 3단계에서 남은 실화면 검수도 함께 수행한다. 6단계 공개 배포는 진행하지 않았다.
