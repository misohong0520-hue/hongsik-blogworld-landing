# 직접 스크롤의 배경 그리기 부담 완화

기준 커밋 `dbfd799`. 사용자가 위아래로 직접 스크롤할 때 약간 끊기는 느낌을 보고했다.

## 확인 범위

- `AnchorFocus`의 휠·터치 처리는 passive이며 진행 중인 메뉴 이동만 취소한다. 직접 스크롤을 계속 가로채는 코드는 발견하지 못했다.
- 상단 메뉴는 이미 requestAnimationFrame으로 묶인 위치 확인을 사용한다. 이것을 병목으로 확정하지 않아 이번 변경에서는 수정하지 않는다.
- 데스크톱 배경은 2634×2634 SVG의 큰 Gaussian blur를 6층으로 표시하며 고유 자산은 4개다. 모바일 고유 자산은 2개다. 브라우저가 캐시할 수 있으므로 ‘매 프레임 6번 계산한다’고 단정하지 않는다.
- 브라우저 도구 연결 제한으로 실제 성능 기록·FPS·사용자 환경의 원인 확정은 하지 못했다.

## 최소 변경

기존 SVG의 블러 결과를 미리 렌더링한 512×512 투명 WebP로 제공한다. CSS의 표시 크기·위치·색 구성·레이어 순서·화면 전체 폭과 콘텐츠·메뉴 코드는 유지한다. 새 스크롤 라이브러리, will-change로 인한 거대한 합성 레이어, 섹션 높이에 영향을 주는 content-visibility는 추가하지 않는다.

`npm run prepare:backgrounds`는 설치된 Next.js의 Sharp를 사용해 자산을 생성한다. 원본 SVG는 보존하며 변경하지 않는다. WebP는 축소된 픽셀에 대해 무손실 압축이며, 원본 SVG와 같은 해상도라는 뜻은 아니다. 전체 파일 크기는 원본 SVG보다 커지지만 복잡한 필터를 실행할 필요가 없는 작은 정적 텍스처를 제공한다.

오프라인 자산 비교에서 데스크톱 자산당 디코딩 픽셀 수는 96.22%, 모바일은 90.01% 줄었다. 이는 SVG 기본 렌더 크기 대비 수치이며 실제 브라우저 메모리·FPS 개선율이 아니다. 흰색·민트색 위로 합성해 원본 크기로 복원한 RGB 차이는 채널당 평균 0.426/255 이하, 최대 4/255였다. 색 차이와 파일별 출처·해시는 `design/background-optimization.json`에 있다. 실제 브라우저 화면 비교를 대신하지 않는다.

검증은 자산 픽셀 비교, 타입 검사, 기존 상호작용 테스트, 정적 빌드·에셋·스타일 연결 검사 및 배포 후 WebP MIME·전체 파일·기존 WordPress 회귀 검사를 포함한다. 끊김이 사라졌다는 결론은 실제 사용자 스크롤 확인이나 브라우저 성능 기록 후에만 내린다.
