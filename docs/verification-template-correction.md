# 원본 템플릿 정렬 수정 검증

날짜: 2026-10-30 (Asia/Seoul). 기준 커밋 `f36d71f`, 작업 브랜치 `codex/landing-template-alignment`.

이전 시안은 원본과 다른 재설계여서 사용자 검토를 통과하지 못했다. 이번에는 원본 프레임을 직접 복제하고, 허용한 내용 교체를 제외한 차이를 노드별로 검사했다.

## 최종 시안

Figma 페이지는 `115:2` (`HongSik · Original layout`)다. 이전 초안 페이지는 `Archive · Superseded layout`으로 구분했다.

## PC 원본 대조

- 원본 581개 노드와 PC의 대응 노드 581개를 매핑했다. 연결된 Play 인스턴스 내부 자식 ID도 실제 저장 후 정규화해 확인했다.
- 최종 PC는 원본 대응 노드 581개와 허용한 교체 콘텐츠 32개를 합친 613개 노드다.
- 부모·기존 자식 순서, x/y·너비·높이·회전·transform, 레이아웃·정렬·여백·간격, 라운딩, 원본 배경·그라데이션·그림자·테두리를 비교했다.
- 캔버스상의 루트 위치 변경만 제외했고 내부 좌표는 비교했다. Figma 복제 시 부동소수점 정규화에 필요한 허용 오차는 0.001px다.
- 결과: `pass: true`, 미승인 변경 노드 0개, 미승인 변경 필드 0개, 미승인 추가 노드 0개.
- 전문 결과는 `design/template-audit.json`, 검증 본문은 `design/figma-template-audit.js`에 있다.

### 비교에서 명시적으로 구분한 내용 교체

- 텍스트 문구와 한글 폰트 대체. Inter Semi Bold에 대응하는 Noto Sans KR 스타일명은 Bold로 사용했다.
- 문구 교체 후에도 원본 텍스트 상자를 유지하기 위한 자동 크기 조정 → 고정 크기 변경. 글자 크기와 상자 위치·크기는 유지했다.
- 로고 영역 내부의 H·전체 앱 이름 배치, 별점·제휴 그래픽·금전 아이콘의 같은 슬롯 내 교체, 아바타 이미지 채우기의 H 교체.
- 혼합 색상 문구인 `or Start Free Trial`을 실제 안내로 바꾸면서 원본 회색을 사용했다.
- 고객사 그래픽과 별을 지울 때 `visible=false`로 인해 그룹 경계가 달라지는 것을 확인했다. 표시 여부를 원상 복구한 뒤 원본 도형의 채우기·선을 비우고 같은 슬롯에 새 그래픽을 놓아 기하를 보존했다.

위 예외를 모든 노드에 포괄 적용하지 않고 해당 노드 ID·속성만 기록했다. 사진 2장·큰 일러스트·장식·섹션·카드 배열은 유지했다.

## 모바일 검사

- 원본 사진·콜라주·3개 큰 기능 카드·체크리스트·3개 과정 카드·연속되는 어두운 문의/푸터를 재사용했다.
- 전체 PC 화면을 평면 이미지로 붙이거나 통째로 축소하지 않았다. 텍스트와 오토레이아웃, 원본 네이티브 그림으로 구성했다.
- 루트 포함 542개 노드, 텍스트 123개, 원본 연결 인스턴스 1개다. 이미지 채우기는 원본 사진과 H 콘텐츠 자산에만 있다.
- 글꼴 누락 0건, 오토레이아웃 자식의 범위 넘침 0건이다. 의도적인 사진 크롭·장식은 별도로 유지한다.
- 첫 화면에서 글자 없이 복제된 두 버튼을 발견해 배경만이 아닌 원본의 텍스트 포함 그룹으로 교체했다. 최종 PNG로 다시 확인했다.
- 상세 결과는 `design/mobile-template-audit.json`, 구성 본문은 `design/figma-template-mobile.js`다.

## 문구·파일·시각 검증

- `template-copy.json`은 메인 프레임의 TEXT 130개 전체를 포함하며 누락·알 수 없는 ID가 없다. 메인 바깥의 홍보 레이어는 대상에서 제외했다.
- PC의 새 문구를 원본 글자 크기로 측정했다. 초과한 2개 문구는 줄이거나 다른 충분한 상자로 이동했고, 문의 주소는 사용 안내 영역에 직접 표시했다.
- 최종 `desktop-template.png`·`mobile-template.png`를 열어 큰 글자 잘림·겹침·빈 버튼·잘못된 카드 수가 없는지 확인했다.
- Figma 스크립트 4개의 AsyncFunction 문법 검사와 상태·카피·감사 JSON 파싱을 통과했다.
- 사이트 실행 코드·의존성은 변경하지 않아 Next 빌드·타입 검사를 반복하지 않았다. 웹 화면의 실제 클릭·반응형·접근성·배포 검증은 후속 단계다.

## 남은 단계

현재 완료 범위는 **2단계 Figma 수정과 인계**다. 실제 웹 구현은 3단계, 원본 컨트롤에 맞는 JavaScript·키보드 동작은 4단계, 브라우저 품질 검수는 5단계, GitHub·AWS 배포는 6단계에서 진행한다.

공개 전 템플릿·사진 이용 조건과 출처 표기를 다시 확인한다. 기존 앱·설정·프롬프트·계정·DB·WordPress·AWS는 수정하지 않았다.
