# 푸터 메뉴·배치 정리

기준 커밋 `3ea2179`, 브랜치 `codex/footer-cleanup`.

사용자가 푸터 전체 개선안을 승인하여 웹 화면에 반영했다. Figma 원본과 기존 앱은 수정하지 않았다.

## 구성

| 영역 | 내용 |
| --- | --- |
| 왼쪽 | 기존 로고·앱 이름·소개 문구·이메일 문의 버튼 하나 |
| 서비스 안내 | 앱 소개 → `#home`, 이용 대상 → `#audience`, 사용 과정 → `#process` |
| 주요 기능 | 자료 준비 → `#feature-sources`, AI 원고 작성 → `#feature-writing`, 검토·발행 → `#feature-publishing` |
| 최하단 | 기존 저작권·도메인 |

기존 ‘안내/블로그 운영 안내’의 중복과 하단 Windows 앱·이메일 문의 링크를 제거했다. 메뉴의 6개 링크는 각기 다른 대상을 가리킨다. 로고의 홈 링크는 유지한다.

푸터 상단 여백은 PC 170px에서 88px, 모바일 56px로 줄였다. 메뉴 글자 크기·간격을 통일했고 기존 고정 최소 높이와 첫 열만 다른 글자 크기를 제거했다. 900px 이하에서는 브랜드와 메뉴를 세로로 쌓으며 메뉴 두 열은 유지한다. 최하단은 구분선과 저작권 한 줄로 정리했다. 배경·브랜드 색상과 왼쪽 문의 버튼 형태는 유지한다.

기능 카드에는 고유 ID와 제목 라벨을 추가했다. 앵커 이동 후 카드의 h3 제목으로 키보드 포커스가 이어지도록 기존 포커스 보완 범위를 확장했다.

## 검증

- `npm run typecheck`, `npm run build` 통과.
- `npm run test:interactions` 9개 통과. 기능 카드 h3로의 포커스 이동과 임시 tabindex 정리를 포함한다.
- `node scripts/verify-export.mjs` 통과. ID 23개 중복 없음, 앵커 22개 대상 존재, 화면 영역 9개 CSS 연결, undefined 클래스 0개, 에셋 경로 172개를 확인했다.
- `node scripts/check-contrast.mjs` 통과. 기존 대비 보완을 유지한다.
- 빌드 HTML에서 푸터 메뉴 2열·링크 6개·고유 대상 6개·이메일 문의 1개·실제 기능 카드 연결 3개를 확인했다.
- 브라우저 도구는 계속 `Local browser use is disabled in Work settings`를 반환했다. 실제 PC·모바일 화면·가로 스크롤·키보드 조작 검수는 아직 수행하지 못했다. 반응형은 소스 구조를 검토했으며 실제 화면 통과를 주장하지 않는다.

로컬 미리보기의 `#footer`로 해당 부분을 바로 확인할 수 있다. 공개 배포는 진행하지 않았다.
